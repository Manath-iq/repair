# Техническое задание

## 1. Стек

**Astro, статическая сборка.** Обоснование:

- страница почти вся статическая, интерактива три куска — калькулятор, форма и два скролл-элемента. Astro отдаёт нулевой JS по умолчанию и подключает его только там, где он нужен;
- у Максима уже написаны и отлажены под Astro скрипт субсетов шрифтов (`scripts/prepare-fonts.mjs`) и генерация OG-превью — переносятся из `stroika-template` и `grand-house-template` без переделки;
- статика раздаётся с CDN, TTFB близок к нулю. На мобильном интернете между объектами это заметно.

**Чего в проекте нет:** GSAP, Lenis, jQuery, Bootstrap, любых UI-китов, CSS-фреймворков. Стили — обычный CSS с переменными.

> Это **одноразовый лендинг**, а не тиражируемое ядро: слой подмены под клиента (`src/clients/<name>.ts`, `npm run new-client`) из `stroika-template` сюда не переносится. Ради этого можно позволить себе уникальную вёрстку секций.
>
> Но **все данные всё равно живут в одном файле** `src/data/content.ts`, а цвета — в `src/styles/tokens.css`. Не ради тиражирования, а чтобы правка цены в двадцати местах не превращалась в поиск по компонентам.

### Структура

```
src/
  data/content.ts        все тексты, цифры, объекты, отзывы, FAQ
  data/calc.ts           коэффициенты калькулятора
  styles/tokens.css      палитра, типографика, радиусы, тени
  styles/base.css
  styles/fonts.css       генерируется скриптом
  components/            по одному .astro на блок из 03
  components/Reveal.astro
  scripts/calc.ts        логика калькулятора, гидратируется
  scripts/plan.ts        скролл-план квартиры
  scripts/form.ts        шаги формы и отправка
  pages/index.astro
  pages/privacy.astro
  pages/og.png.ts
public/media/            фотографии и SVG-чертежи
scripts/prepare-fonts.mjs
```

## 2. Калькулятор сметы

**Главное требование: результат показывается без телефона.** Из всех проверенных сайтов ниши так делает один. Человек, увидевший порядок цены, — квалифицированный лид: он не отвалится на первом же звонке, услышав сумму.

### Формула

```
цена_м2 = база[уровень]
        × коэф_объекта
        × коэф_площади
        × коэф_санузлов
        × коэф_срочности

нижняя_граница = цена_м2 × площадь
верхняя_граница = нижняя_граница × 1.15

срок = round( база_дней[уровень] × (0.45 + 0.55 × площадь / 60) × коэф_срочности_срок )
```

### Коэффициенты (`src/data/calc.ts`)

**База, ₽/м², только работы:**

| Уровень | ₽/м² | База дней |
|---|---|---|
| Косметический | 3 900 | 14 |
| Черновой | 4 900 | 25 |
| Капитальный | 7 400 | 45 |
| Под ключ | 9 900 | **62** |
| Дизайнерский | 12 900 | 85 |

**Тип объекта:**

| Тип | Цена | Срок |
|---|---|---|
| Новостройка с предчистовой | ×0.92 | ×0.85 |
| Новостройка без отделки | ×1.00 | ×1.00 |
| Вторичка | ×1.10 | ×1.08 |
| Вторичка с перепланировкой | ×1.22 | ×1.22 |

**Площадь** (маленькие квартиры дороже за метр — постоянные работы те же):

| Площадь | Коэффициент |
|---|---|
| до 35 м² | ×1.12 |
| 35–59 м² | ×1.05 |
| 60–89 м² | ×1.00 |
| 90–129 м² | ×0.96 |
| 130 м² и больше | ×0.93 |

**Санузлы:** 1 → ×1.00 · 2 → ×1.08 · 3 → ×1.14
**Срочность:** обычный → цена ×1.00, срок ×1.00 · сжатый → цена ×1.15, срок ×0.82

**Материалы** — отдельный коэффициент к сумме работ:

| Уровень | Коэффициент |
|---|---|
| Косметический | ×0.55 |
| Черновой | ×0.45 |
| Капитальный | ×0.62 |
| Под ключ | ×0.65 |
| Дизайнерский | ×0.74 |

Коэффициенты откалиброваны по шести объектам портфолио из `06` — проверить можно умножением, суммы сходятся в пределах 10%.

### Разбивка по статьям

Доли фиксированы и в сумме дают ровно 100. **Сборка должна падать, если сумма ≠ 100** — лучше упасть, чем показать смету, которая не сходится.

```
Демонтаж и вывоз мусора       6
Перегородки и проёмы          8
Электрика                    14
Сантехника                   11
Стяжка пола                   9
Штукатурка стен и потолков   18
Плиточные работы             15
Малярные работы              12
Двери, приборы, установка     7
                            ---
                            100
```

### Контрольный расчёт

60 м² · новостройка без отделки · под ключ · 1 санузел · обычный срок:

```
9 900 × 1.00 × 1.00 × 1.00 × 1.00 = 9 900 ₽/м²
нижняя  = 594 000 ₽
верхняя = 683 100 ₽  →  показываем «от 594 000 до 683 000 ₽»
срок    = 62 × (0.45 + 0.55) × 1.00 = 62 дня
```

Совпадает с заголовком первого экрана и с суммой этапов `7 + 8 + 12 + 16 + 14 + 5 = 62`. **Эти три числа обязаны сходиться всегда** — если меняете база_дней «под ключ», меняйте и этапы.

> Сроки в портфолио — **фактические по конкретным объектам** и совпадать с калькулятором не обязаны. Калькулятор даёт ориентир, реальный объект — факт. Это нормально и специально оговорено в тексте под калькулятором.

### Поведение

- Пересчёт при каждом изменении поля, **без анимации счётчика**. Цифра просто становится другой.
- Состояние пишется в `location.hash`, чтобы расчёт можно было скинуть ссылкой. Персональных данных в hash нет — только площадь и выбранные варианты.
- Кнопка «Прислать подробную смету» открывает форму с уже подставленными параметрами.
- Округление: цены до тысяч вниз, срок — до целых дней.

## 3. Скролл-план квартиры

SVG-план двухкомнатной квартиры вид сверху, шесть групп-слоёв с `data-layer="1".."6"`.

Слой включается, когда соответствующая карточка этапа входит в экран, и **больше не выключается**: квартира отделывается, а не мигает.

### Грабли, на которые уже наступили в `stroika-template`

**`IntersectionObserver` сообщает только текущее состояние.** Всё, через что пролистнули быстрым махом или перепрыгнули по якорю, наблюдателю не достаётся вообще. Поэтому:

- блоки, оказавшиеся выше экрана на момент инициализации, показываются сразу;
- при включении слоя `N` **достраиваются все слои до него**. Иначе на плане появляется чистовая отделка на квартире без стяжки.

**Липкий блок в гриде.** `align-items: start` ужимает колонку по содержимому, и `position: sticky` внутри неё перестаёт работать — ехать некуда. Колонка с планом обязана растягиваться на высоту строки.

**Скоуп стилей Astro.** Компонент `Reveal` рисует элемент за вызывающего, и атрибут `data-astro-cid-*` на него сам не попадает — приходит пропом. Без `{...rest}` в `Reveal.astro` правила вида `.stage__item[data-astro-cid-…]` не совпадают ни с чем, и раскладка блока молча пропадает: ни ошибки в консоли, ни падения сборки.

### Проверки на сборке

Сборка падает, если конфиг противоречив:

- доли оплаты по этапам не дают в сумме 100;
- доли статей сметы не дают в сумме 100;
- сумма дней по этапам не равна `база_дней['под ключ']`;
- номера слоёв не 1..6 без пропусков;
- у объекта портфолио нет цены.

## 4. Приём заявок

**Токен Telegram-бота в браузер не кладём.** В собранном сайте нет сервера, любой ключ в JS виден всем, кто открыл исходники.

Схема:

```
форма на сайте  →  POST JSON  →  функция на Cloudflare Workers  →  Telegram sendMessage
                                  (токен в переменных окружения)
```

Тело запроса:

```json
{ "subject": "Расчёт сметы", "answers": {...}, "name": "", "phone": "", "channel": "whatsapp", "page": "" }
```

**Порядок деградации:**

1. `endpoint` задан → `POST` на него;
2. `endpoint` пуст, есть WhatsApp → открывается `wa.me` с готовым текстом заявки;
3. нет и его → `mailto`.

Вариант с WhatsApp — рабочий минимум на старте: заявка доходит без единой строчки бэкенда. Для демо этого достаточно, и **в демо-сборке используется именно он**, с номером-маской.

**Защита от спама:** honeypot-поле и проверка, что форма заполнялась дольше 3 секунд. Капчу не ставим — она стоит конверсии больше, чем спама отсекает.

> ⚠️ **В демо-сборке `<meta name="robots" content="noindex, nofollow">`.** Демо не должно попасть в выдачу по коммерческим запросам и конкурировать с сайтами реальных компаний, которым мы же его показываем.

### OG-превью

`/og.png` собирается на этапе сборки: название, заголовок, три показателя, телефон. Ссылку кидают в WhatsApp — там происходит половина первых касаний, и превью открывают заметно охотнее, чем голый домен.

**Три грабли `resvg`,** на которые уже потрачено время в `grand-house-template`:

- **woff2 он не читает.** Шрифты распаковываются в ttf через `wawoff2`.
- **`fontBuffers` молча игнорируется** — весь текст уезжает в системный serif. Работает только `fontFiles`: ttf кладутся в `.cache/og-fonts` и передаются путями.
- **Распаковка строго последовательная.** `wawoff2` — обёртка над Emscripten-модулем с общей памятью, параллельные вызовы затирают друг другу вывод. Файлы получаются правильного размера, но с испорченными таблицами — выглядит как «шрифт не подхватился», весь текст в квадратах.
- Вариативные шрифты resvg не инстанцирует и берёт начертание по умолчанию. Для превью подключаются отдельные статические `@fontsource/*`, а имя шрифта читается из таблицы `name` внутри ttf — оно не совпадает с CSS и включает вес («Onest SemiBold»).

## 6. Производительность

Страница фотографическая, поэтому бюджет жёсткий:

| Показатель | Бюджет |
|---|---|
| LCP на 4G, мобильный | < 2,0 с |
| CLS | < 0,05 |
| JS на первом экране | < 25 КБ |
| JS всего | < 60 КБ |
| Шрифты всего | < 120 КБ |
| Hero-изображение | < 180 КБ |
| Вес страницы до первого экрана | < 450 КБ |

**Как достигается:**

- AVIF с запасным WebP, `<picture>` с `srcset` на 4 ширины: 480 / 768 / 1200 / 1800;
- у hero-изображения `fetchpriority="high"`, у всех остальных `loading="lazy"` и `decoding="async"`;
- `width` и `height` проставлены у каждого изображения — иначе CLS;
- шрифты предзагружаются только те начертания, что есть на первом экране (Geologica 600, Onest 400);
- скрипты калькулятора, плана и формы грузятся отложенно — `client:visible`;
- SVG-чертежи инлайнятся, а не грузятся файлами: их немного и они нужны для анимации выносок.

## 7. Правовое

- Страница `/privacy` — политика обработки персональных данных с датой последней редакции.
- Чекбокс согласия в форме **не предзаполнен**, ссылка на политику рядом.
- Реквизиты в футере: наименование, ИНН, ОГРН(ИП), юридический адрес.
- Cookie-баннера нет: сторонних трекеров, кроме Метрики, на странице нет, а уведомление о ней достаточно разместить в политике.
